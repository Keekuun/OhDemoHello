# 15 性能优化

> 学习目标：让 App 滑起来不卡、打开快、省电。知道卡了去哪查。

## 一、先记住一条原则

**别提前优化。** 先让功能跑通，真觉得卡了，再按本篇的方法找瓶颈。瞎优化等于白忙活。

## 二、长列表：LazyForEach（最重要的优化）

普通 `ForEach`：1000 条数据，**一次性全建出来**，卡死。
`LazyForEach`：**屏幕里只显示 10 条，就只建 10 个**，滑到哪建到哪。

```typescript
// ① 数据要包一层 IDataSource
class MyDataSource implements IDataSource {
  private list: string[] = [];

  constructor(list: string[]) {
    this.list = list;
  }

  totalCount(): number { return this.list.length; }
  getData(index: number): string { return this.list[index]; }
  registerDataChangeListener(listener: DataChangeListener): void {}
  unregisterDataChangeListener(listener: DataChangeListener): void {}
}

// ② 用 LazyForEach 渲染
@State dataSource: MyDataSource = new MyDataSource(this.bigList);

List() {
  LazyForEach(this.dataSource, (item: string) => {
    ListItem() { Text(item) }
  }, (item: string) => item)
}
.cachedCount(3)   // 屏幕外多缓存 3 条，滑动更顺
```

**口诀：数据超过一屏，就用 LazyForEach。**

## 三、减少刷新范围

`@State` 一变，**用到它的组件**都会刷新。变量放错位置，刷新一大片：

```typescript
// ❌ 整个大组件用一个 @State，改一个数字整个页面重绘
// ✅ 把会变的部分拆成小组件，各管各的 @State
@Component
struct LikeButton {
  @State likeCount: number = 0;   // 只有这个按钮自己刷新
  build() { ... }
}
```

**口诀：状态尽量下沉到最小组件，刷新范围越小越流畅。**

## 四、图片优化

| 做法 | 收益 |
|------|------|
| 图片压缩后再放进项目 | 包体积小、加载快 |
| 网络图片用 `.objectFit(ImageFit.Cover)` | 避免变形还省内存 |
| 列表里图片别太大 | 一屏几十张图，大图直接爆内存 |

## 五、冷启动优化（打开 App 更快）

用户点图标到看到首页的时间，越短越好：

1. **`EntryAbility` 里别干重活**——网络请求、数据库初始化挪到首页 `aboutToAppear` 里异步做
2. **首页别套太深**——嵌套层级每多一层，布局计算多一分
3. **首屏数据能缓存就缓存**——先显示上次的缓存，再悄悄刷新

## 六、找到卡顿：用工具，别猜

DevEco Studio 自带 **Profiler**（菜单 `Tools → Profiler`）：

| 看什么 | 说明 |
|--------|------|
| **CPU** | 哪段代码最耗 CPU，揪出它 |
| **内存** | 一直涨不回落 = 内存泄漏 |
| **帧率 FPS** | 低于 60 就是卡，看滑动时掉不掉帧 |
| **启动时间** | 冷启动花了多少毫秒 |

**排查流程**：感觉卡 → 开 Profiler 录一段操作 → 看帧率曲线哪里掉 → 定位到具体函数 → 优化它。

## 七、常见卡顿原因速查

| 症状 | 可能原因 | 药方 |
|------|----------|------|
| 列表滑动卡 | 用了 ForEach 没用 LazyForEach | 换 LazyForEach |
| 页面打开慢 | aboutToAppear 里同步干重活 | 改异步、延后加载 |
| 点一下整个页面闪 | @State 放太高层 | 状态下沉到小组件 |
| 越用越卡 | 定时器/请求没取消 | aboutToDisappear 里收工 |
| 动画掉帧 | 动画改了 width/height | 改用 translate/scale |

## 动手练

1. 用 `LazyForEach` 改造一个 1000 条数据的列表，对比改造前后的滑动流畅度。
2. 开 Profiler 录一次 App 冷启动，看启动耗时多少毫秒。

## 小结

- 长列表必须 `LazyForEach`，只渲染看得见的
- 状态下沉，刷新范围越小越好
- 卡了用 Profiler 量，别凭感觉猜
- 先跑通再优化，别提前瞎折腾
