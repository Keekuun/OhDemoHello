# 13 生命周期与沉浸式

> 学习目标：搞懂 App 从启动到关闭经历哪些「时刻」，以及内容怎么铺满全屏。
> 项目实例：`EntryAbility.ets`、每个页面的 `aboutToAppear`

## 一、三层生命周期

鸿蒙 App 有三个层面的「一生」：

```
① Ability 层（整个应用窗口）
   onCreate → onWindowStageCreate → onForeground → onBackground → onWindowStageDestroy → onDestroy

② 页面层（@Entry 的页面）
   aboutToAppear → （页面显示中）→ aboutToDisappear

③ 组件层（每个 @Component）
   aboutToAppear → build → aboutToDisappear → aboutToReuse（复用时）
```

## 二、Ability 生命周期（看 EntryAbility.ets）

```typescript
export default class EntryAbility extends UIAbility {
  onCreate() {
    // App 进程创建。做：初始化日志、SDK
  }

  onWindowStageCreate(windowStage) {
    // 窗口创建。做：设置全屏、加载第一个页面
    windowStage.loadContent('pages/Index');
  }

  onForeground() {
    // App 回到前台（用户切回来）。做：刷新数据、恢复播放
  }

  onBackground() {
    // App 退到后台（用户切走）。做：暂停视频、保存草稿
  }

  onDestroy() {
    // App 销毁。做：释放资源
  }
}
```

**记忆场景**：你正在看视频，突然切去回微信——
- 切走瞬间：`onBackground` → 暂停播放
- 切回瞬间：`onForeground` → 继续播放

## 三、页面/组件生命周期

```typescript
@Entry
@Component
struct MyPage {
  aboutToAppear(): void {
    // 页面即将显示。做：拉网络数据、读本地缓存
    // 本项目每个页面都在这里接路由参数
  }

  aboutToDisappear(): void {
    // 页面即将消失。做：取消网络请求、关定时器
  }

  build() { ... }
}
```

**黄金搭档**：
- `aboutToAppear` 里「开工」（拉数据、开定时器）
- `aboutToDisappear` 里「收工」（取消请求、关定时器）

不开定时器会忘关，App 越来越卡——这就是「内存泄漏」的日常版。

## 四、沉浸式：内容铺满全屏

默认情况下，App 内容被限制在「状态栏以下、导航栏以上」。沉浸式就是让内容铺满整个屏幕，看起来更高级。

本项目的做法（`EntryAbility.ets`）：

```typescript
// ① 窗口设为全屏布局
mainWindow.setWindowLayoutFullScreen(true);

// ② 量出状态栏、导航栏的高度，存到全局
const avoidArea = mainWindow.getWindowAvoidArea(window.AvoidAreaType.TYPE_SYSTEM);
AppStorage.setOrCreate('statusBarHeight', px2vp(avoidArea.topRect.height));
AppStorage.setOrCreate('navBarHeight', px2vp(avoidArea.bottomRect.height));
```

然后每个页面自己决定「哪里要躲开」：

```typescript
// 页面顶部留状态栏高度（标题栏不被时间/电量盖住）
.padding({ top: this.statusBarHeight })

// 或者整个页面扩展到安全区外（背景图铺满，内容自己躲）
.expandSafeArea([SafeAreaType.SYSTEM], [SafeAreaEdge.TOP])
```

## 五、两种适配策略

| 策略 | 效果 | 适合 |
|------|------|------|
| 加 padding 躲开 | 标题栏在状态栏下面，背景色块不延伸 | 普通内容页 |
| `expandSafeArea` 延伸 | 背景/图片铺到状态栏底下，内容再单独躲 | 大图头图、渐变背景页 |

本项目首页用 `expandSafeArea`（顶部色块延伸进状态栏），二级页面用 padding（标题栏躲开）。

## 六、px2vp 是什么

```typescript
AppStorage.setOrCreate('statusBarHeight', px2vp(avoidArea.topRect.height));
```

系统量出来的高度单位是 `px`（物理像素），代码里布局用 `vp`（虚拟像素）。
`px2vp()` 负责换算，保证不同分辨率手机上看起来一样大。**记住：系统给的 px，用之前先 px2vp。**

## 动手练

1. 在 `EntryAbility.ets` 的每个生命周期方法里加一句 `hilog.info(...)`，然后操作 App（启动、切后台、切回、杀掉），在 Log 面板观察打印顺序。
2. 把某个页面的 `.padding({ top: this.statusBarHeight })` 删掉，跑起来看标题被状态栏盖住的效果，体会它的作用。

## 小结

- 生命周期 = App 的「时刻表」：什么时候该初始化、该暂停、该收工
- 页面数据在 `aboutToAppear` 拉，资源在 `aboutToDisappear` 收
- 沉浸式两步：窗口设全屏 + 页面自己躲状态栏
- 系统尺寸单位是 px，用 `px2vp` 换算
