# 06 状态管理详解

> 学习目标：搞懂 `@State` 家族，让数据在页面之间「流动」起来。
> 这是鸿蒙开发**最重要也最容易晕**的一章，慢慢看。

## 一、为什么需要状态管理

回忆第 03 篇：**界面是数据的影子**。
问题来了：数据存在哪？谁变了要通知谁刷新？这就是状态管理要解决的。

## 二、一张表看懂所有装饰器

| 装饰器 | 数据存在哪 | 谁能改 | 典型场景 |
|--------|-----------|--------|----------|
| `@State` | 本组件 | 自己 | 页面内部的小状态（开关、输入内容） |
| `@Prop` | 父组件传的副本 | 自己改不影响父 | 子组件要父组件的数据，但各改各的 |
| `@Link` | 父组件的引用 | 双方改都同步 | 子组件改了，父组件也要跟着变 |
| `@Provide` / `@Consume` | 祖先组件 | 后代直接用 | 跨很多层传数据，不用一层层递 |
| `@StorageProp` | 全局 AppStorage | 只读绑定 | 读全局值（如状态栏高度） |
| `@StorageLink` | 全局 AppStorage | 双向同步 | 改全局值，所有页面跟着变 |
| `@Observed` / `@ObjectLink` | 类对象 | 对象内部变化也能感知 | 嵌套对象的深层刷新 |

别被吓到，**90% 的场景只用 `@State` 和 `@StorageProp` 两个**。

## 三、@State：页面自己的状态

```typescript
@Component
struct Counter {
  @State count: number = 0;    // ① 声明状态

  build() {
    Column() {
      Text(`点了 ${this.count} 次`)   // ② 界面用它
      Button('+1').onClick(() => {
        this.count++;            // ③ 改它 → 界面自动刷新
      })
    }
  }
}
```

**规则**：`@State` 变量必须用 `this.xxx` 访问，改它界面就刷新。

## 四、@StorageProp：读全局数据

项目实例——每个页面顶部都要知道「状态栏有多高」才能留出空间：

```typescript
// EntryAbility.ets 里存进去（App 启动时执行一次）：
AppStorage.setOrCreate('statusBarHeight', px2vp(avoidArea.topRect.height));

// 任何页面里读出来用：
@StorageProp('statusBarHeight') statusBarHeight: number = 0;
```

这样每个页面都能拿到状态栏高度，不用一个个传。看 `ProfilePage.ets` 第 2 行就是这个用法。

## 五、@Prop 和 @Link：父子之间传数据

```typescript
// 子组件
@Component
struct Child {
  @Prop value1: number;   // 父传我一份拷贝，我改我的
  @Link value2: number;   // 父传我一根"连线"，我改 = 父改

  build() {
    Button('改Link').onClick(() => { this.value2++; })  // 父组件同步刷新
  }
}

// 父组件
@Entry @Component
struct Parent {
  @State num: number = 0;
  build() {
    Column() {
      Child({ value1: this.num, value2: $num })  // 注意 @Link 用 $ 符号传
    }
  }
}
```

**记忆法**：`@Prop` 是「复印件」，`@Link` 是「遥控器」。

## 六、@Provide / @Consume：跨层传数据

爷爷组件的数据想给重孙用，中间爸爸不想经手：

```typescript
// 爷爷
@Provide themeColor: string = 'blue';

// 重孙（中间多少层都行）
@Consume themeColor: string;   // 自动对上同名变量
```

## 七、什么时候界面不刷新？（常见坑）

```typescript
@State list: string[] = ['a'];

// ❌ 这样改，界面不刷新（数组内部变了，但引用没变）
this.list.push('b');

// ✅ 这样才行（重新赋值，引用变了）
this.list = [...this.list, 'b'];
```

**口诀：改对象/数组的内容后，要重新赋值一次，系统才知道变了。**

如果是嵌套很深的对象，就需要 `@Observed` + `@ObjectLink` 组合，用到再查。

## 小结

- 页面内部状态用 `@State`，全局共享用 `AppStorage` + `@StorageProp`
- 父子传数据：拷贝用 `@Prop`，联动用 `@Link`（传参带 `$`）
- 数组/对象改完要**重新赋值**才触发刷新——新手第一大坑
