# 11 权限与安全

> 学习目标：搞懂鸿蒙的权限机制——什么时候登记、什么时候弹窗、为什么乱申请会装不上。
> 项目实例：`PermissionPage.ets`（本项目踩过真实坑，见下文）

## 一、权限分两类

| 类型 | 例子 | 要不要弹窗问用户 |
|------|------|------------------|
| **普通权限** | 联网 INTERNET、查网络状态 | 不用，登记就能用 |
| **敏感权限** | 相机、麦克风、定位、相册 | 要！运行时弹窗，用户点了同意才能用 |

## 二、完整流程（以相机为例）

### 第 1 步：module.json5 登记

```json5
"requestPermissions": [
  {
    "name": "ohos.permission.CAMERA",
    "reason": "$string:perm_camera_reason",   // 申请理由，用户能看到
    "usedScene": {
      "abilities": ["EntryAbility"],
      "when": "inuse"                          // 使用期间才要
    }
  }
]
```

`reason` 写在 `string.json` 里：「用于拍照和录像功能」——**要写人话，用户看得懂才容易点同意**。

### 第 2 步：代码里检查 + 请求

```typescript
import { abilityAccessCtrl, Permissions } from '@kit.AbilityKit';

const atManager = abilityAccessCtrl.createAtManager();
const permission: Permissions = 'ohos.permission.CAMERA';

// ① 先检查：现在有没有权限？
const status = atManager.checkAccessTokenSync(
  bundleInfo.accessTokenId,
  permission
);

if (status === abilityAccessCtrl.GrantStatus.PERMISSION_GRANTED) {
  // 已有权限，直接用相机
} else {
  // ② 没有权限，弹窗请求
  const result = await atManager.requestPermissionsFromUser(
    getContext(this),
    [permission]
  );
  if (result.authResults[0] === 0) {
    // 用户点了「允许」
  } else {
    // 用户点了「拒绝」——要给个友好提示，别闪退
  }
}
```

**口诀：先检查（check），没有再请求（request），被拒绝要兜底。**

## 三、本项目的真实教训：乱申请权限 = 装不上

这个项目开发时踩过坑，记录在案：

> 一开始申请了 15 项权限（联系人、日历、蓝牙等），结果**安装直接失败**，报错：
> `Install Failed: grant request permissions failed`

**原因**：有些权限是普通应用**根本没资格申请**的（系统级权限），申请了系统直接拒绝安装。

**解决**：只保留真正用到的 6~8 项常用权限：
`CAMERA`、`MICROPHONE`、`READ_MEDIA`、`WRITE_MEDIA`、`LOCATION`、`APPROXIMATELY_LOCATION`、`INTERNET`、`GET_NETWORK_INFO`

**教训：权限最小化原则——用不到的一律不申请。** 这也是应用商店审核的要求。

## 四、用户拒绝了怎么办

用户拒绝后，下次再请求系统可能直接不弹窗了。这时候要引导用户去系统设置里手动开：

```typescript
import { bundleManager } from '@kit.AbilityKit';

// 跳转到本应用的系统设置页
const want = {
  bundleName: 'com.huawei.hmos.settings',
  abilityName: 'com.huawei.hmos.settings.MainAbility',
  uri: 'application_info_entry',
  parameters: { pushParams: 'com.example.ohdemohello' }  // 你的包名
};
getContext(this).startAbility(want);
```

界面上给个弹窗：「需要相机权限才能拍照，是否去设置开启？」

## 五、安全编码好习惯

| 习惯 | 为什么 |
|------|--------|
| 权限最小化 | 申请越少，用户越信任，审核越好过 |
| 敏感数据不打印日志 | `hilog` 里的内容可能被读到 |
| 网络请求用 https | http 明文传输，会被窃听 |
| 用户输入要校验 | 防止恶意输入搞崩 App |
| token 存 Preferences 而不是写死 | 写死等于把钥匙放门口 |

## 动手练

1. 打开 `PermissionPage.ets`，点「检测权限」看看当前各项权限状态。
2. 试着点「请求」相机权限，观察系统弹窗；拒绝一次，再请求看有什么变化。
3. 思考：如果用户拒绝了定位权限，你的「附近的人」功能界面应该长什么样？（画个兜底 UI）

## 小结

- 普通权限登记即用，敏感权限要运行时弹窗
- 流程：检查 → 请求 → 拒绝兜底
- **权限最小化**：乱申请会让 App 装不上（本项目真实踩坑）
- 被拒绝后引导用户去系统设置开启
