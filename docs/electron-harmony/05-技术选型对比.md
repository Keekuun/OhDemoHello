# 05 技术选型对比

> 学习目标：做鸿蒙应用，到底选 ArkTS 原生、Electron 还是别的？看完能拍板。

## 一、四条主流路线

| 维度 | **ArkTS 原生**（本项目） | **Electron 鸿蒙版** | Qt 鸿蒙版 | Flutter 鸿蒙版 |
|------|------------------------|--------------------|-----------|---------------|
| 技术栈 | ArkTS + ArkUI | HTML/CSS/JS | C++/QML | Dart |
| 目标设备 | 手机/平板/PC/手表/车机 | **仅鸿蒙 PC** | PC/嵌入式 | 手机/平板/PC |
| 性能 | ⭐⭐⭐⭐⭐ 最好 | ⭐⭐⭐ 软件渲染 | ⭐⭐⭐⭐ | ⭐⭐⭐⭐ |
| 包体积 | 小（MB 级） | **大（200MB+，带 Chromium）** | 中 | 中 |
| 开发效率 | 中学（要学 ArkTS） | 高（前端直接上手） | 低 | 中高 |
| 系统能力 | 全部 | 大部分（经适配层） | 部分 | 大部分 |
| 生态成熟度 | 官方主推，文档全 | SIG 维护，快速迭代 | 社区移植 | 社区适配 |
| 存量迁移 | 重写 | **Electron 应用直接搬** | Qt 应用直接搬 | 重写 UI |

## 二、决策流程图

```
你要做什么应用？
│
├── 手机/平板应用 ────────────→ ArkTS 原生（唯一正解，Electron 跑不了）
│
├── 鸿蒙 PC 桌面应用
│   ├── 已有 Electron 应用要迁移 ──→ Electron 鸿蒙版（成本最低）
│   ├── 团队全是前端，要快出活 ────→ Electron 鸿蒙版
│   ├── 重度性能（视频处理/3D/大型工具）→ Qt 或 ArkTS 原生
│   └── 追求极致体验和系统集成 ────→ ArkTS 原生
│
└── 全场景（手机+PC 都要）
    ├── 一套代码 ────────────────→ ArkTS 原生（一次开发多端部署）
    └── 各端最优体验 ────────────→ 手机 ArkTS + PC Electron（复用 Web 业务代码）
```

## 三、什么时候选 Electron 鸿蒙版

✅ **适合**：
- 手上已经有 Electron 应用（编辑器、建模工具、IM 桌面端），想上鸿蒙 PC
- 团队是前端背景，不想为单个平台学 ArkTS
- 应用界面复杂但性能要求不极端（文档、表单、数据展示类）
- 需要复用大量 Web 生态库（图表、编辑器组件等）

❌ **不适合**：
- 要做手机/平板应用（根本跑不了）
- 对包体积敏感（一个空壳就 200MB+）
- 重度 GPU 场景（硬件加速当前必须关，纯软件渲染）
- 依赖大量 C++ 原生模块的项目（适配成本高）

## 四、和本项目的配合姿势

「鸿蒙百宝箱」是 ArkTS 原生应用，它和 Electron 不是竞争关系，而是**互补**：

| 需求 | 用什么 |
|------|--------|
| 手机上的鸿蒙功能演示 | 本项目（ArkTS） |
| PC 上的桌面工具 | Electron 鸿蒙版 |
| 一套代码全端跑 | ArkTS（ArkUI 支持多端） |

实际项目中常见的组合：**移动端 ArkTS 原生 + PC 端 Electron**，业务逻辑层（网络请求、数据模型）用纯 TS 写成共用包，两端各写各的 UI。

## 五、学习建议

1. **先学 ArkTS 原生**（本项目 docs 的 16 篇教程）——理解鸿蒙的权限、沙箱、生命周期、签名，这些概念在 Electron 鸿蒙版里**完全一样**
2. 再学 Electron 基础（主进程/渲染进程/IPC）——Electron 官方文档
3. 最后看本套文档的 01~04 篇——学鸿蒙特有的适配差异

> 一句话：**鸿蒙的系统知识是通用的，变的只是 UI 技术栈**。

## 小结

- 手机平板 → 只能 ArkTS；PC 存量 Web 迁移 → Electron；重度性能 → Qt/原生
- Electron 鸿蒙版的核心价值：**让前端和存量 Electron 应用低成本进入鸿蒙 PC 生态**
- 系统层知识（权限/沙箱/签名/生命周期）两条路线通用，先学原生再打 Electron 基础最顺
