# 04 报错速查与避坑指南

> 遇到报错别慌，先在本页 Ctrl+F 搜关键字。收录鸿蒙 Electron 适配最高频的真实报错。

## 一、启动/运行类

### 🔴 白屏（最高频）
- **现象**：应用启动后窗口一片空白
- **根因**：没禁用硬件加速，GPU 进程在鸿蒙上跑不起来
- **解法**：`main.js` 第一行加 `app.disableHardwareAcceleration();`（必须在 `app.whenReady()` 之前）
- **经验**：这是鸿蒙 Electron 第一定律，写死成肌肉记忆

### 🔴 报错 801（手机/平板上运行）
- **现象**：在非 2in1 设备上安装运行报 801
- **根因**：鸿蒙 Electron 只支持鸿蒙 PC（2in1）
- **解法**：换鸿蒙 PC 真机或 2in1 模拟器
- **经验**：别想在手机上跑 Electron，手机请用 ArkTS（比如本项目）

### 🔴 `Cannot find module 'electron'`
- **现象**：启动就报找不到 electron 模块
- **根因**：`package.json` 的 dependencies 里写了 `electron`
- **解法**：删掉。鸿蒙运行时由 `libelectron.so` 提供 electron 模块
- **经验**：鸿蒙 Electron 是「宿主提供」的，`npm install electron` 是错的

### 🔴 `Cannot find resource 'main.js'`
- **现象**：启动找不到入口文件
- **根因**：应用代码放错了目录
- **解法**：必须在 `web_engine/src/main/resources/resfile/resources/app/` 下，且 `package.json` 的 `main` 字段指向正确
- **经验**：TS/Vue/React 项目要先编译成纯 JS 再放进来

### 🔴 `napi_unwrap fail`（启动 0 秒闪退）
- **现象**：API 23+ / HarmonyOS 6.1 设备上启动即退出，hilog 里有 `napi_unwrap fail`
- **根因**：用了旧版 libelectron（XComponent 渲染路径），和新系统协议不兼容
- **解法**：换**新版 libelectron**（双模块包：electron 主模块 + web_engine HSP，走 WebAbility 方案）
- **经验**：新设备必须新版库，旧版从根上跑不起来

### 🔴 GPU 进程崩溃
- **现象**：hilog 里 GPU process crash
- **根因**：同白屏——硬件加速没关干净
- **解法**：确认 `disableHardwareAcceleration()` 在所有窗口创建之前执行

## 二、构建/集成类

### 🟠 构建失败「找不到 SO 库」
- **根因**：`electron/libs/arm64-v8a/` 下库文件缺失
- **解法**：确认 4 个文件都在：`libelectron.so`、`libadapter.so`、`libffmpeg.so`、`libc++_shared.so`（最后一个来自鸿蒙 SDK：`sdk/openharmony/native/llvm/lib/aarch64-linux-ohos/`）

### 🟠 `.so` 文件只有 130 字节
- **根因**：git 仓库的大文件没拉下来（git-lfs 没装或没执行）
- **解法**：`git lfs install` 后重新 `git lfs pull`
- **经验**：凡是从仓库拿的 .so，先看文件大小正不正常

### 🟠 签名失败 / 安装失败
- **根因 A**：没配置签名 → DevEco `Project Structure → Signing Configs` 自动签名
- **根因 B**：申请了 ACL 受限权限但证书没批下来 → 先把 `SYSTEM_FLOAT_WINDOW`、`READ_PASTEBOARD` 等受限权限注释掉
- **经验**：先让最小权限集跑通，再逐个加权限

### 🟠 `ohpm install` 卡死
- **解法**：换国内镜像源，新机第一件事就配

## 三、三方库类

### 🟡 某个 npm 库一引入就崩
按决策树排查（详见第 03 篇第六节）：
1. 带 C++ addon？→ 要鸿蒙工具链交叉编译，或换纯 JS 替代
2. 带预编译二进制？→ 基本没救，换库或功能降级
3. 内部判断 `process.platform`？→ 它不认识 `'ohos'`，patch 或换库

### 🟡 `@electron/remote` 异常
- **根因**：它对 Electron 原生 binding 的假设在鸿蒙上不完全成立
- **解法**：加 patch 脚本，或改回标准 IPC（`ipcMain.handle` + `ipcRenderer.invoke`）

## 四、调试类

### 🔵 DevEco 控制台看不到日志
- **根因**：Electron 主进程日志不进 DevEco 控制台
- **解法**：用 `hilog` 看主进程，`Ctrl + Alt + I` 开 DevTools 看渲染进程，崩溃看 faultlog

### 🔵 不知道文件存哪去了
- **解法**：记住 `app.getPath('userData')` = `/data/storage/el2/base/files`，用系统「文件管理」应用查看

## 五、避坑总清单（打印贴墙版）

```
□ main.js 第一行：app.disableHardwareAcceleration()
□ package.json 里没有 electron 依赖
□ 代码放在 web_engine/.../resources/app/
□ 4 个 .so 库齐全且大小正常（不是 130 字节）
□ 签名已配置
□ 只在 2in1 设备/模拟器运行
□ TS/框架项目先编译成纯 JS 再放入
□ 单窗口架构，loadURL 切页面
□ 文件读写走 app.getPath('userData')
□ 日志看 hilog，不看 DevEco 控制台
□ 新系统设备用新版 libelectron
□ 受限权限申请不下来就先注释
```

## 小结

- 90% 的问题集中在：白屏（没关加速）、放错目录、带了 electron 依赖、缺 .so、没签名
- 报错先搜本页，找不到再去 [openharmony-sig/electron](https://gitcode.com/openharmony-sig/electron) 提 issue
