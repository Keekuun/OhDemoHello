# 03 开发实战与适配要点

> 学习目标：写出能在鸿蒙 PC 上稳定运行的 Electron 应用，绕开所有已知的坑。

## 一、最小可用 main.js（鸿蒙版模板）

```javascript
const { app, BrowserWindow } = require('electron');
const path = require('path');

// ✅ 第一行就必须是这句：禁用硬件加速，否则白屏！
app.disableHardwareAcceleration();

let mainWindow = null;

function createWindow() {
  mainWindow = new BrowserWindow({
    width: 1180,
    height: 700,
    minWidth: 800,
    minHeight: 600,
    show: false,                    // 等加载完再显示，避免白屏闪烁
    backgroundColor: '#ffffff',     // 鸿蒙上建议纯白底，不要用 transparent
    webPreferences: {
      nodeIntegration: false,       // 安全基线：渲染进程不开 Node
      contextIsolation: true,       // 安全基线：上下文隔离
      preload: path.join(__dirname, 'preload.js')
    }
  });

  mainWindow.once('ready-to-show', () => mainWindow.show());
  mainWindow.loadFile('index.html');
}

app.whenReady().then(createWindow);

app.on('window-all-closed', () => app.quit());
```

## 二、package.json 的鸿蒙规矩

```json
{
  "name": "my-harmony-app",
  "version": "1.0.0",
  "main": "main.js",
  "dependencies": {
  }
}
```

**铁律**：
- ❌ **绝对不能**把 `electron` 写进 dependencies/devDependencies——运行时由 `libelectron.so` 提供，写了反而报 `Cannot find module 'electron'`
- ❌ 不能有 C++ addon 类依赖（better-sqlite3、sharp、esbuild 等）
- ✅ 纯 JS 的依赖（lodash、dayjs 等）可以正常用，记得把 `node_modules` 一起拷进 `resources/app/`

## 三、识别鸿蒙运行时

同一份代码可能既跑桌面又跑鸿蒙，需要判断当前在哪：

```javascript
function isHarmonyOS() {
  return process.platform === 'ohos'                          // 最直接
    || __dirname.includes('/data/storage/el1/bundle/')        // 鸿蒙沙箱特征路径
    || (process.resourcesPath || '').includes('/data/storage/el1/bundle/');
}

if (isHarmonyOS()) {
  // 鸿蒙专属逻辑：比如禁用某些不支持的功能
}
```

> ⚠️ 很多三方库内部用 `process.platform` 判断平台，它们不认识 `'ohos'` 这个值，可能直接报错。遇到这种库，要么 patch，要么换库。

## 四、窗口管理：单窗口策略

鸿蒙版多窗口能力受限，**推荐单窗口架构**：

```javascript
// ❌ 不推荐：开多个 BrowserWindow
// ✅ 推荐：一个窗口，用 loadURL 切换内容
function openSettings() {
  mainWindow.loadURL('https://myapp.com/settings');
  // 或 loadFile('settings.html')
}
```

窗口按钮（最小化/最大化/关闭）：
- `mainWindow.setWindowButtonVisibility(true)` 可显示系统窗口按钮
- 若用 `frame: false` 自定义标题栏，要自己实现拖拽区和三个按钮，并处理鸿蒙窗口状态

## 五、文件与沙箱路径

鸿蒙是沙箱文件系统，**不是想读哪就读哪**：

| 沙箱路径 | 实际映射 | 用途 |
|----------|----------|------|
| `/data/storage/el1/bundle` | 安装包目录 | 只读，你的 resources/app 在这 |
| `/data/storage/el2/base/files` | 应用数据目录 | **Electron userData 默认在这**，读写用户数据 |
| `/data/storage/el2/base/files/...` | 同上 | 日志、缓存、用户文档 |

```javascript
const { app } = require('electron');
const path = require('path');
const fs = require('fs');

// 正确：用 app.getPath 拿用户数据目录
const userFile = path.join(app.getPath('userData'), 'config.json');
fs.writeFileSync(userFile, JSON.stringify({ theme: 'dark' }));

// 查看用户数据：通过系统「文件管理」应用
```

要访问 Download/Documents/Desktop 等公共目录，需要在 `module.json5` 申请对应权限（见第 02 篇权限表）。

## 六、三方库适配决策树

```
这个 npm 库能在鸿蒙用吗？
├── 纯 JS 写的？
│   └── ✅ 大概率能用（注意 process.platform 判断）
├── 带 C++ addon（node-gyp）？
│   └── ⚠️ 要用鸿蒙工具链交叉编译（cmake-js + aarch64-linux-ohos）
│       或者找纯 JS 替代品（如 better-sqlite3 → sql.js）
├── 带预编译二进制（esbuild、sharp）？
│   └── ❌ 基本用不了，找替代或做功能降级
└── 用了 @electron/remote？
    └── ⚠️ 有兼容问题，需要 patch 或改用 IPC
```

**功能降级**是常用策略：鸿蒙版砍掉不支持的次要功能，核心功能保住。

## 七、调试手段

| 手段 | 用法 | 场景 |
|------|------|------|
| **DevTools** | 运行后按 `Ctrl + Alt + I` | 看界面、调渲染进程 |
| **hilog** | `hilog | grep 你的tag` | 看主进程日志、系统错误 |
| **faultlog** | 崩溃后 `hdc shell` 查 faultlog | 闪退排查 |
| **console → hilog** | 主进程 console 输出会进 hilog | 日常调试 |

> 注意：DevEco 的控制台**看不到** Electron 主进程输出，别在那找日志。

## 八、性能建议

1. **硬件加速已关**，是纯软件渲染——界面避免大面积复杂动画、3D
2. `libelectron.so` 近 200MB，包体积大，发布前考虑精简 locales（只留 zh-CN/en-US）
3. 首窗口用 `show: false` + `ready-to-show`，避免启动白屏闪烁
4. 重计算任务放 Worker 线程，别堵主进程

## 九、一个真实适配案例的经验（CHINER 元数建模）

- 把「拷贝资源到 resfile」固化成脚本 `build-ohos-package.js`，别手动复制
- 用 `ohos-runtime.js` 集中管理运行时判断和窗口参数
- 窗口参数按平台区分：鸿蒙上 `backgroundColor: '#ffffff'`，桌面上用 `transparent`
- 给鸿蒙版单独写冒烟测试（启动、窗口、基础 IPC）

## 小结

- 模板三件套：首行关硬件加速、`show:false` 防白屏、安全 webPreferences
- package.json 不放 electron、不用 C++ addon 库
- 单窗口 + loadURL 切换；文件走 `app.getPath('userData')` 沙箱
- 调试靠 Ctrl+Alt+I 和 hilog，别在 DevEco 控制台找日志
